# White Cup — визуальные отклонения и обоснования

Лендинг сохраняет логику шести референсных экранов: hero → меню → «о месте» → форматы визита → события → адреса. Ниже перечислены детали, которые намеренно отличаются от статичных референсов или уточняют их в рабочем интерфейсе.

| Деталь в референсе | Реализовано | Почему это сделано | Где проверить |
| --- | --- | --- | --- |
| Шесть отдельных экранов | Один прокручиваемый лендинг с мягкими границами сцен и sticky-навигацией | Пользователь не теряет контекст между экранами; якоря сохраняют быстрый переход к меню, событиям и адресам | `src/App.tsx`, `src/components/StickyNav.tsx` |
| Статичные границы между экранами | Между каждой сценой добавлен inert pure-CSS paper-bridge: нейтральный ivory/paper градиент с rounded panel, мягкой petrol-тенью, тонким orange marker и короткой рукописной подписью; route/ticket/raster artwork удалён. Desktop-шапка теперь full-bleed от `top: 0`: на hero она полупрозрачная, после hero — плотная opaque paper-плашка без просвечивания контента | Сцены читаются как один маршрут White Cup, но каждое полотно остаётся самостоятельным; bridge не вмешивается в семантический поток, не содержит `<img>` и уважает reduced-motion. | Полноэкранные прямоугольные артборды | На desktop сцены получили небольшой paper-gutter, мягкий радиус и лёгкую внешнюю тень; верхний край hero оставлен открытым для слияния с full-bleed header. ## Источники медиа

- Документальные изображения — только локально сохранённые и визуально проверенные публичные кадры из Yandex Maps; они распределены по сценам как интерьер/атмосфера/локация.
- Нормальный hero-path использует `hero-clean-base-v2-*.webp` (ImageGen reference edit), `hero-bagel-plate-reference-edit-*.webp` (ImageGen edit + deterministic chroma alpha), существующий coffee WebP, `hero-doodles-exact.png`, `hero-route-cup-1672.webp`, `hero-skyline-exact.png` и reference logo crop. Это отдельные decorative reference-art, не documentary evidence; underline рисуется CSS и не является runtime-изображением. Ранние POC/Remove Background experiments удалены из `public/media`; authoring-файлы активных слоёв сохранены только в `docs/reference/assets/`.
- Menu/Visit footer skyline использует отдельный responsive alpha-preserving `rhythm-skyline-reference-edit-720w.webp`/`1200w.webp`; он извлечён из rhythm/Visit reference и не подменяет documentary venue photo. Hero продолжает использовать собственный `hero-skyline-exact.png`, чтобы сохранить orange sun и исходный hero provenance.
- About использует отдельный responsive foreground `about-pastry-plate-reference-edit-v2-*.webp`, созданный через Image Generation Skill по supplied About-reference. Полная тарелка сохранена в alpha-слое; она — editorial reference-art, не подтверждение блюда или меню White Cup.
- `Remove Background Local` был действительно прогнан для нового bagel/plate edit, но его результат отброшен: он потерял белую тарелку. В production применён контролируемый chroma alpha; проверочные authoring PNG оставлены только в `docs/reference/assets/`.
- Меню загружает только production WebP: responsive-пару `menu-clean-base-*.webp` и responsive-пары `menu-{cappuccino,bagel,waffle,syrniki,cheesecake,oatmeal,shakshuka,croissant}-*.webp`. Исходные authoring PNG использовались как локальные промежуточные файлы генерации и намеренно не публикуются; provenance каждого runtime-слоя зафиксирован в `src/data/media.ts`.
- Исторические title-extract PNG/WebP для Hero/Menu/About/Visit/Events/Locations намеренно выведены из runtime в пользу локального живого Neucha-текста по указанию пользователя. Проверенные исходные crop-artifacts остаются в `docs/reference/assets/` только как reference/provenance и не считаются документальными изображениями White Cup.
- На desktop 1536px карта и интерьер Locations используют 1672px WebP-источники: в Chromium это устраняет paint-gap при эффективном 125% zoom, сохраняя отдельный mobile 960px crop.
- VK остаётся внешней ссылкой, но его недоступные для проверки публикации не превращаются в факты лендинга.
